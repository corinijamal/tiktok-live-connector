# ساحة المعركة — TikTok Battle Arena

لعبة معركة فردية للبث المباشر على TikTok. المشاهدون ينضمون بـ 8 نقرات
(إعجاب) على الشاشة، ويظهرون كفقاعات بصورهم الشخصية داخل ساحة دائرية
يتصادمون فيها، مع نظام رتب وهجمات هدايا وتأثيرات صوتية وبصرية.

## آلية اللعبة

- **الانضمام**: بالنقر (الإعجاب ❤️) على الشاشة 8 مرات على الأقل — لا
  يحتاج المشاهد يكتب أي تعليق. بمجرد ما يوصل 8 نقرات، يدخل الساحة فورًا
  بعدد نقاطه المتراكمة من نفس النقرات (80 نقطة، أي 8 نقرات × 10).
- **النقاط بعد الانضمام**: كل نقرة/إعجاب إضافية = ‎+10 نقاط خضراء مباشرة.
- **الاصطدام**: عند تصادم فقاعتين، كل طرف يفقد 10 نقاط من الطرف الآخر
  (بنفس قيمة النقرة الواحدة، عشان التصادم يحس بتناسب حقيقي مع النقاط).
  إذا وصلت نقاط أحدهم إلى صفر، **يخرج من الساحة فورًا** ويُمنح الطرف الآخر
  "قتلة" (kill) تظهر بجانب اسمه (💀 العدد).
- **هجوم الهدايا**: أي هدية تُطلق **وابلًا مستمرًا من القذائف** يستمر 10
  ثوانٍ بمعدل 3 قذائف بالثانية (30 قذيفة إجمالًا)، كل قذيفة تُلحق ضررًا
  يساوي عدد عملات الهدية بالضبط، وتستهدف صاحب أعلى نقاط حاليًا في كل
  مرة (يعيد التصويب تلقائيًا لو تغيّر المتصدّر أثناء الوابل). تظهر رسالة
  "قام <المرسل> بتفعيل المستوى <الرقم>" مرة واحدة فقط عند أول قذيفة، حسب
  قيمة الهدية (1–6)، مصحوبة بصوت. إذا كان المُرسِل لسا خارج الساحة،
  الهدية تُدخله فورًا (تحسب له أي نقرات سابقة جمعها بدل ما تُهدر).
- **الشفرة (Blade)**: مؤشر نشاط حي، مو شارة دائمة — تظهر حول الفقاعة
  فقط أثناء النقر الفعلي، وتختفي بتلاشي ناعم بعد حوالي 3 ثوانٍ من توقف
  النقر. لونها وعدد أسنانها يعكسان رتبة اللاعب إن وصلها، وإلا تظهر بلون
  افتراضي محايد لأي لاعب نشط حتى لو ما وصل رتبة بعد.
- **الرتب (المستويات)**: تراكم النقاط يكبّر حجم الفقاعة حتى حد أقصى (1000
  نقطة، أي 100 نقرة)، وبعده تُمنح رتبة مميزة تلوّن الشفرة:
  🥉 برونزي (1000) → 🥈 فضي (2500) → 🥇 ذهبي (5000) → 💎 ماسي (10000) →
  🔴 ياقوتي (20000) → 👑 أسطوري (40000).
- **الجولات**: كل جولة 3 دقائق. الفائز هو صاحب أعلى نقاط عند انتهاء الوقت.
  تبدأ جولة جديدة تلقائيًا حتى يتم إيقاف اللعبة يدويًا من لوحة التحكم.
  ملاحظة: اللاعبون المُقصَون (Eliminated) لا يعودون تلقائيًا بالجولة
  التالية — يحتاجون 8 نقرات جديدة من جديد.
- **مؤثرات صوتية**: أصوات تصادم وتفعيل مستوى تُولَّد مباشرة بالمتصفح (لا
  تحتاج ملفات خارجية)، وتُفعَّل تلقائيًا عند أول ضغطة على أزرار لوحة
  التحكم (متطلب المتصفحات لتشغيل الصوت).

## لوحة التحكم

لوحة التحكم مخفية افتراضيًا، وتظهر بالضغط على زر الترس ⚙️ أسفل يمين
الشاشة — بحيث لا تبقى ظاهرة فوق البث طول الوقت.

## التشغيل محليًا

```bash
npm install
npm start
```

بعدها افتح `http://localhost:3000` في المتصفح.

1. اضغط زر الترس ⚙️ لإظهار لوحة التحكم.
2. اكتب اسم المستخدم على TikTok (بدون @) واضغط "اتصال بالبث".
3. (اختياري) اضبط "مدة الجولة" بالدقائق و"عدد الجولات" (0 = غير محدود،
   يعني تستمر الجولات تلقائيًا حتى الإيقاف اليدوي كما كانت من قبل) ثم
   اضغط "حفظ إعدادات المسابقة". التعديل ينطبق على الجولة القادمة —
   الجولة الجارية حاليًا (إن وُجدت) تكمل بموعدها الأصلي.
4. اضغط "بدء اللعبة" لبدء الجولة الأولى.
5. اضغط "إيقاف اللعبة" لإيقاف الجولات المتتالية يدويًا في أي وقت.
6. اضغط "إعادة تعيين الساحة" لمسح كل اللاعبين الحاليين فورًا (مفيد لو
   احتجت تبدأ نظيف بدون قطع الاتصال بالبث أو إيقاف الجولة).

عند تحديد عدد جولات (غير 0) وانتهاء آخر جولة، تتوقف اللعبة تلقائيًا
(زي ضغط "إيقاف اللعبة") وتظهر شاشة "🏁 انتهت المسابقة" مع بطل آخر جولة،
بدل ما تكمل لجولة جديدة تلقائيًا — تبدأ مسابقة جديدة بالضغط على "بدء
اللعبة" مرة ثانية.

## الاختبار بدون بث مباشر

```bash
# إعجابات/نقرات (8+ تُدخل الساحة تلقائيًا، بدون أي تعليق)
curl -X POST http://localhost:3000/api/simulate/like \
  -H "Content-Type: application/json" \
  -d '{"userId":"test1","nickname":"أحمد","count":8}'

# إرسال هدية (قيمة عملات) — تُطلق هجومًا على الأعلى نقاطًا
curl -X POST http://localhost:3000/api/simulate/gift \
  -H "Content-Type: application/json" \
  -d '{"userId":"test1","nickname":"أحمد","coinValue":50}'
```

## اختبار منطق اللعبة

```bash
node test-engine.js
```

يتحقق من: شرط الانضمام (8 نقرات فقط)، دقة الحساب حتى مع قيم نصية من
تيك توك، الإقصاء عند وصول النقاط للصفر واحتساب القتلات، ضرر الاصطدام
الجديد (10)، وابل قذائف الهدايا المستمر واستهدافه للأعلى نقاطًا (يشمل
تحقق زمني فعلي من استمرار إطلاق القذائف)، إلغاء الوابل عند الإيقاف،
مؤشر النقر النشط (tapping)، وتصفير الساحة عند إعادة الاتصال أو إعادة
التعيين اليدوية.

## النشر على Render

نفس أسلوب مشاريعك السابقة:
1. ادفع المشروع إلى GitHub.
2. أنشئ Web Service جديد على Render، اربطه بالمستودع.
3. Build Command: `npm install` — Start Command: `npm start`.
4. فعّل Auto-Deploy من إعدادات GitHub integration.

## ملاحظة حول مكتبة tiktok-live-connector

هذا المشروع يستخدم إصدار `2.4.4` من المكتبة. بيانات المستخدم الفعلية
القادمة من تيك توك غير ثابتة الشكل عبر أنواع الأحداث المختلفة (أحيانًا
تكون متداخلة بعمق غير متوقع)، لذلك `server.js` يجرّب الأشكال الأبسط
والأكثر ثقة أولاً (`data.user.*` ثم `data.*` المسطّحة) قبل ما يلجأ
للبحث التكراري العميق (`findUserDeep` / `findAvatarUrlDeep`) كحل أخير —
لأن القفز للبحث العميق مباشرة كان أحيانًا يطلع تطابق خاطئ بدل الحقل
الصحيح المتاح مباشرة.

**تأكيد مهم من الـ logs الفعلية**: حدث اللايك بهذا الإصدار يستخدم
`data.count` (عدد النقرات بهذا الحدث تحديدًا) و`data.total` (إجمالي
البث كامل) بدل الأسماء الموثّقة `likeCount`/`totalLikeCount`. الكود
يجرّب الاسمين الموثّقين أولاً ثم `count` كحل مؤكد، فلو رجعت المكتبة
تستخدم الأسماء الموثّقة بإصدار مستقبلي، يستمر يشتغل بدون تعديل.

لو تغيّرت المكتبة مرة أخرى، أول خطوة هي مراقبة سطور `CHAT EXTRACTED:` /
`LIKE EXTRACTED:` / `PENDING JOIN:` في الـ logs (تطبع أول عدة أحداث بعد
كل اتصال، بالإضافة لتتبع تراكم كل مشاهد لحاله) للتأكد من ثبات الهوية
المستخرجة بين نقرة وأخرى لنفس الشخص. سطر `LIKE EXTRACTED` يطبع أيضًا
كل حقل بالبيانات اسمه يحتوي "count"/"total"، كإجراء احترازي لو تغيّر
اسم الحقل الحقيقي مرة ثانية.

## نقاط قابلة للتخصيص لاحقًا

- كل ثوابت اللعبة في أعلى `server/gameEngine.js`: مدة الجولة، عتبة
  الانضمام (`JOIN_LIKE_THRESHOLD`، حاليًا 8 — كانت 20 لكن خُفّضت لأنها
  كانت تحتاج نقرًا متواصلًا طويل نسبيًا لمعظم المشاهدين)، عدد النقاط لكل نقرة
  (`POINTS_PER_LIKE`)، ضرر الاصطدام (`BASE_COLLISION_DAMAGE`)، مدة ومعدل
  وابل قذائف الهدايا (`GIFT_BARRAGE_DURATION_MS`، `GIFT_SHOTS_PER_SECOND`)،
  مدة بقاء الشفرة بعد توقف النقر (`ACTIVE_TAP_WINDOW_MS`)، الحد الأقصى
  لحجم الفقاعة، عتبات الرتب وألوانها (`RANKS`)، سرعة الحركة (`MAX_SPEED`).
- مستويات الهدايا (`levelForCoinValue`) قابلة للتعديل حسب قيم الهدايا
  الشائعة في بثوثك.
- لا يوجد حفظ دائم (MongoDB) في هذه النسخة — كل البيانات في الذاكرة
  وتُصفّر عند إعادة تشغيل السيرفر أو تغيير الحساب المتصل.
